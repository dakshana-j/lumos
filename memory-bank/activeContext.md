## Current Focus

Branch: `feat/review-pr-mode`.
PR review capability fully implemented, refined, and tested.
Review checks are now repo-agnostic and cover 10 structured checks.

### What Changed (this session)

- **PR review prompt made repo-agnostic**: Removed all Lighthouse/Breeze
  hardcoding from `src/prompts/pr-review-prompt.ts`. Role, title format,
  test path heuristics, and conventions reference are now generic so the
  `reviewPr()` capability works against any repository.
- **PR Title check generalised**: Was `BZ-XXXX: type(scope): description`.
  Now accepts any ticket prefix (JIRA-123, GH-456, BZ-789, etc.) with a
  valid type qualifier. Judgement-based — flags clear violations only.
- **Test Coverage paths generalised**: Was Lighthouse-specific `src/routes/`,
  `src/lib/…`. Now generic heuristic: `src/`, `lib/`, `app/`, `packages/`.
- **Conventions section renamed**: `[LIGHTHOUSE CONVENTIONS REFERENCE]` →
  `[PROJECT CONVENTIONS REFERENCE]`.
- **Four new hard-fail checks added** (checks 7–10):
  - **Check 7 — How to Test (Dev-Authored)**: The "Steps for Testing" section
    must be written by the developer, NOT auto-generated by AI tools (Yama,
    Copilot, etc.). Specific detection signals listed in the prompt (generic
    boilerplate, no feature-specific detail, LLM-style phrasing, missing
    concrete values).
  - **Check 8 — Video Proof (Mocking Mode)**: PR must include a screen
    recording/GIF/link showing the feature working with mocked backend.
    SKIP only for non-UI changes (config-only, CI scripts, docs).
  - **Check 9 — Video Proof (Non-Mocking Mode)**: A separate recording
    against real backend/staging is required. Both must be present.
    SKIP only for non-UI changes.
  - **Check 10 — Dev Code-Change Proof**: Developer must attach proof of
    manual testing (screenshots, before/after, logs, recordings). SKIP for
    pure refactors/docs/type-only changes with explicit justification.
- **Comment table expanded**: Review comment now has 10 rows (was 6).
- **Verdict rules updated**: Checks 7–10 are hard-fails (trigger
  `❌ Changes Required`).
- **Test suite updated** (`test/pr-review.test.ts`):
  - `LUMOS_REVIEW_COMMENT` and `LUMOS_REVIEW_COMMENT_FAIL` updated to 10-row table.
  - `checksRun` assertion updated: 6 → 10.
  - New `describe` block "reviewPr — new checks (checks 7–10)" with 5 tests:
    auto-generated How to Test, missing mocking video, missing non-mocking video,
    missing dev proof, non-UI skip path.

### Recent Decisions

- **Repo-agnostic by design**: `reviewPr()` is a universal PR quality gate,
  not a Lighthouse-only tool. Project-specific conventions go in
  `memory-bank/pr-review-conventions.md` (loaded at runtime).
- **Yama awareness**: Check 7 explicitly names Yama as an example of an AI
  tool that auto-fills PR descriptions. The check looks for signals that the
  "How to Test" section was machine-generated rather than authored by a dev.
- **Both video types are mandatory**: Mocking and non-mocking recordings are
  separate checks because they validate different execution paths. A developer
  may have one but forget the other.
- **SKIP scope is narrow**: Video and dev-proof checks skip only for changes
  with no observable runtime behaviour. Justification required in Notes column.
